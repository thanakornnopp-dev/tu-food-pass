# 🍜 TU Food Pass - สุ่มอาหาร & นักล่าส่วนลด มหาวิทยาลัยธรรมศาสตร์
> **โปรเจกต์นวัตกรรมและการเป็นผู้ประกอบการ (TU109 Innovation & Entrepreneurship)**  
> **สถาปัตยกรรม:** Offline-First Web Application (ทำงานออฟไลน์ได้ 100% โดยไม่ต้องต่ออินเทอร์เน็ต)

---

## 🎯 1. ที่มาและแนวคิดธุรกิจ (Business Rationale & Value Proposition)

แรงบันดาลใจจากระบบสุ่มอาหารในมหาวิทยาลัย (เช่น ฟังก์ชัน *Food & Lifestyle* ในเครือข่าย *baanTU มธ.*) ซึ่งพบ Pain Point สำคัญ:
1. **สุ่มแค่ชื่อร้าน แต่ไม่ตอบโจทย์ "สั่งอะไรดี / ราคาเท่าไร":** นศ. มักไปยืนเก้ๆ กังๆ หน้าร้าน
2. **ขาดแรงจูงใจในการใช้งานต่อเนื่อง (Lack of Retention & Monetization):** เว็บสุ่มทั่วไปไม่มีโมเดลรายได้ที่ชัดเจน
3. **ปัญหาการคุมงบประมาณของเด็กหอ:** กินอาหารตามใจจนเงินหมดก่อนสิ้นเดือน
4. **ความขัดแย้งเวลาไปกินข้าวเป็นกลุ่ม:** สุ่มแล้วเพื่อนคนอื่นไม่ยอมกินตาม

**TU Food Pass** จึงแก้ปัญหาด้วยโมเดล **Subscription Economy แบบ 3-Tier**:
* **Tier 1: Eater Pass (39 บาท/เดือน):** สุ่มปุ๊บ ได้คูปองลด 5-15% หรือฟรีท็อปปิ้งทันที ดึงคนเข้าร้านพันธมิตร (Win-Win)
* **Tier 2: Meal Plan Creator (79 บาท/เดือน):** ระบบสุ่มและจัดตารางอาหาร 7 วัน 21 มื้อ พร้อมการันตีเงินที่ประหยัดได้มากกว่าค่า Sub
* **Tier 3: Feature Unlocked / VIP (99 บาท/เดือน):** สุ่มสายมูตามสีเสื้อมงคลประจำวัน + ตัวกรองสุขภาพละเอียด + ระบบสุ่มกับแก๊งเพื่อน (Party Veto Mode)

## 🔌 2. ทำไมถึงผ่านมาตรฐาน "ใช้งานได้ภายใต้เงื่อนไขออฟไลน์ (Offline-First)"

เว็บแอปพลิเคชันนี้ออกแบบมาให้ทำงานได้โดย **ไม่ต้องต่ออินเทอร์เน็ต (Zero External Network Dependency)**:
1. **Embedded Mock Database:** ข้อมูลร้านอาหารจริงรอบ มธ. รังสิต (SC, วิศวะ EN, วิทย์ SCI, ทิวสน, HOW, OLB, อินเตอร์โซน, ยิม 4/6/7, เชียงราก) บันทึกอยู่ในไฟล์ `js/data.js`
2. **Local Storage Engine:** กระเป๋าคูปอง, ประวัติการใช้สิทธิ์, แผนอาหาร, และสถานะแพ็กเกจ ถูกจัดเก็บใน LocalStorage ของเบราว์เซอร์อย่างปลอดภัย ปิดเครื่องแล้วเปิดใหม่ข้อมูลไม่หาย
3. **Web Audio API Sound Engine:** เสียงคลิก, เสียงหมุนวงล้อ, และเสียงเพลงฉลอง ชนะการสุ่ม สร้างขึ้นด้วยสัญญาณคลื่นสังเคราะห์ของเบราว์เซอร์โดยตรง ไม่ต้องโหลดไฟล์เสียงภายนอก
4. **HTML5 Canvas Animation:** ระบบวงล้อฟิสิกส์และระบบโปรย Confetti พัฒนาด้วย Canvas บริสุทธิ์ ทำงานได้ลื่นไหลทุกหน้าจอ

## 🚀 3. วิธีเปิดใช้งานและเดโม่ส่งอาจารย์ (Demo Walkthrough)

### ขั้นตอนการเปิดใช้งาน:
* เพียงแค่ **ดับเบิลคลิกไฟล์ `index.html`** เพื่อเปิดบน Google Chrome, Safari, Firefox หรือ Microsoft Edge บนเครื่องของคุณ
* สามารถเปิดในขณะที่ **ปิด Wi-Fi / ตัดการเชื่อมต่ออินเทอร์เน็ต** ได้ 100%

### ลำดับขั้นตอนการนำเสนอให้อาจารย์ดู (Presentation Flow):
1. **โชว์แถบ `🎓 TU109 Demo Bar` ด้านบนสุด:**
   - กดปุ่ม **`1. Free User`**: สาธิตการสุ่มแบบพื้นฐานเหมือนเว็บในคลิปเดิม (ไม่ได้รับคูปอง)
   - กดปุ่ม **`2. Eater Pass ⭐`**: กดสุ่มอีกครั้ง จะมีเอฟเฟกต์ Confetti และ **คูปองส่วนลดเด้งขึ้นมาทันที** พร้อมพาไปดูที่แท็บ **"กระเป๋าคูปอง (My Wallet)"** เพื่อกดใช้สิทธิ์หน้าร้าน
   - กดปุ่ม **`3. Meal Plan 🍱`**: เปิดแท็บ **"จัดเซต 7 วัน"** แสดงตาราง 21 มื้อ คำนวณงบประมาณทั้งสัปดาห์ พร้อมตัวเลขสรุปเงินที่ประหยัดได้
   - กดปุ่ม **`4. VIP All-Access 👑`**: 
     - เปิดแท็บ **"สายมู/สุขภาพ"** โชว์การสุ่มเมนูอาหารตามสีเสื้อมงคลประจำวันและคำทำนาย
     - เปิดแท็บ **"สุ่มกับเพื่อน"** โชว์ระบบ Party Room ที่เพื่อนในโต๊ะสามารถกด **Veto** เพื่อสุ่มใหม่จนกว่าทุกคนจะแฮปปี้

## 🏆 5. จุดเด่นสำหรับคะแนนสอบ TU109 (Grading Criteria Alignment)

| เกณฑ์การประเมิน TU109 | สิ่งที่โปรเจกต์ตอบโจทย์ |
| :--- | :--- |
| **Problem Identification** | แก้ปัญหาเรื่องคิดไม่ออก, การคุมงบการเงินนักศึกษา, และความขัดแย้งเวลาเลือกอาหารกับเพื่อน |
| **Value Proposition** | มอบความคุ้มค่าที่จับต้องได้ทันที (เงินที่ประหยัดได้จากคูปอง > ค่าบริการ Subscription) |
| **Business Model Feasibility** | มีกระแสรายได้สม่ำเสมอ (Recurring Revenue) จากผู้ใช้ และรายได้ค่าโฆษณา/โปรโมตจากร้านค้า (B2B2C) |
| **Technical Feasibility** | สถาปัตยกรรม Offline-First ตอบโจทย์ข้อกำหนดอาจารย์ มีเสถียรภาพสูง ไม่พึ่งพาคลาวด์ภายนอก |
| **User Experience (UX/UI)** | ออกแบบตามมาตรฐานวิศวกรรมซอฟต์แวร์ สวยงาม ใช้งานง่าย มีเกมและปฏิสัมพันธ์ที่น่าประทับใจ |
