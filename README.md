# 🍜 TU Food Pass - สุ่มอาหาร & นักล่าส่วนลด มหาวิทยาลัยธรรมศาสตร์
> **โปรเจกต์นวัตกรรมและการเป็นผู้ประกอบการ (TU109 Innovation & Entrepreneurship)**  
> **สถาปัตยกรรม:** Offline-First Web App (PWA) ออกแบบสำหรับ iPhone

---

## 🎯 1. ที่มาและแนวคิดธุรกิจ (Business Rationale & Value Proposition)

แรงบันดาลใจจากระบบสุ่มอาหารในมหาวิทยาลัย (เช่น ฟังก์ชัน *Food & Lifestyle* ในเครือข่าย *baanTU มธ.*) ซึ่งพบ Pain Point สำคัญ:
1. **สุ่มแค่ชื่อร้าน แต่ไม่ตอบโจทย์ "สั่งอะไรดี / ราคาเท่าไร":** นศ. มักไปยืนเก้ๆ กังๆ หน้าร้าน
2. **ขาดแรงจูงใจในการใช้งานต่อเนื่อง (Lack of Retention & Monetization):** เว็บสุ่มทั่วไปไม่มีโมเดลรายได้ที่ชัดเจน
3. **ปัญหาการคุมงบประมาณของเด็กหอ:** กินอาหารตามใจจนเงินหมดก่อนสิ้นเดือน
4. **ความขัดแย้งเวลาไปกินข้าวเป็นกลุ่ม:** สุ่มแล้วเพื่อนคนอื่นไม่ยอมกินตาม

**TU Food Pass** จึงแก้ปัญหาด้วยโมเดล **Subscription Economy แบบ 3-Tier**:
* **Tier 1: Eater Pass (39 บาท/เดือน):** สุ่มปุ๊บ ได้คูปองลด 5-15% หรือฟรีท็อปปิ้งทันที ดึงคนเข้าร้านพันธมิตร (Win-Win)
* **Tier 2: Meal Plan Creator (79 บาท/เดือน):** ระบบสุ่มและจัดตารางอาหาร 7 วัน 21 มื้อ พร้อมการันตีเงินที่ประหยัดได้มากกว่าค่า Sub
* **Tier 3: Feature Unlocked / VIP (99 บาท/เดือน):** สุ่มสายมูตามสีเสื้อมงคลประจำวัน + ตัวกรองสุขภาพละเอียด + ระบบสุ่มกับแก๊งเพื่อน (Party Veto Mode)

## 🔌 2. ทำงานออฟไลน์ (Offline-First) บน iPhone

แอปนี้ไม่พึ่งอินเทอร์เน็ตตอนใช้งาน: ไม่โหลดฟอนต์/สคริปต์จากภายนอก, ข้อมูลร้านอยู่ใน `js/data.js`, สถานะทั้งหมด (แพ็กเกจ คูปอง แผนอาหาร) เก็บใน LocalStorage, เสียงสร้างด้วย Web Audio, คอนเฟตตีวาดด้วย Canvas

**ติดตั้งลง iPhone (ทำครั้งเดียวตอนมีเน็ต):**
1. เปิดเว็บที่โฮสต์ไว้ (เช่น GitHub Pages) ด้วย Safari บน iPhone
2. แตะ Share → **Add to Home Screen**
3. เปิดแอปจากไอคอนบนหน้าจอโฮมหนึ่งครั้ง แล้วดูที่แท็บ **บัตรฉัน** ต้องขึ้นว่า “พร้อมใช้งานออฟไลน์”
4. ปิด Wi-Fi/เน็ต ลองเปิดอีกครั้งเพื่อทดสอบก่อนวันพรีเซนต์

> เปิดไฟล์ `index.html` ด้วยการดับเบิลคลิกได้เพื่อดูหน้าตา แต่ Service Worker (แคชออฟไลน์) ทำงานเฉพาะบน HTTPS/localhost

## 🚀 3. ลำดับสาธิตให้อาจารย์ (บน iPhone แชร์จอไป Mac)

**แผงผู้นำเสนอ:** แตะโลโก้ “TU Food Pass” ด้านบน **3 ครั้งติด** เพื่อสลับแพ็กเกจ ตั้งเวลาจำลอง (ร้านที่เปิดอยู่) เปิด/ปิดเสียง และล้างข้อมูลทดลอง

1. **Free:** แท็บ *สุ่ม* → กด “สุ่มเลย” ตั๋วร้านอาหารพิมพ์ออกมา แต่คูปองถูกล็อก
2. **Eater Pass ฿39:** กด “ปลดล็อก” → ชำระเงินจำลอง → สุ่มอีกครั้งได้คูปอง → แท็บ *กระเป๋า* → “ใช้คูปองนี้”
3. **Meal Plan ฿79:** แท็บ *แผนอาหาร* → ตั้งงบ → จัด 21 มื้อ ดูสรุปว่าคูปองคุ้มกว่าค่าสมาชิกเท่าไร
4. **VIP ฿99:** โหมด *สายมู* (สีมงคลประจำวัน), ตัวกรองสุขภาพ, และ *กับเพื่อน* (Party Veto)

## 📁 4. โครงสร้างไฟล์

```
tu-food-pass/
├── index.html        # โครงหน้า + ชุดไอคอน SVG (ไม่มีอีโมจิ)
├── css/
│   ├── fonts.css     # ฟอนต์ Mitr + Bai Jamjuree (เก็บในโปรเจกต์)
│   └── app.css       # ดีไซน์ทั้งหมด: ตั๋วบนพื้นแดงเลือดหมู เงิน/ทอง
├── fonts/            # ไฟล์ฟอนต์ .woff2
├── js/
│   ├── data.js       # ร้านอาหาร เมนู ราคา คูปอง (ข้อมูลตัวอย่าง)
│   ├── audio.js      # เสียงสังเคราะห์ Web Audio
│   ├── core.js       # state, แพ็กเกจ, sheet, toast, confetti, router
│   ├── spin.js       # สุ่ม (รีลตั๋ว, สายมู, กับเพื่อน)
│   ├── stalls.js     # ร้านค้า
│   ├── plan.js       # แผนอาหาร 7 วัน
│   ├── wallet.js     # กระเป๋าคูปอง
│   ├── pass.js       # บัตรฉัน, แพ็กเกจ, ชำระเงินจำลอง
│   └── app.js        # เริ่มแอป, แผงผู้นำเสนอ, ออฟไลน์
├── sw.js             # Service Worker (เปลี่ยน CACHE_VERSION ทุกครั้งที่แก้ไฟล์)
├── manifest.json     # PWA
├── PRODUCT.md        # บริบทผลิตภัณฑ์
└── DESIGN.md         # ระบบดีไซน์
```

**ใส่รูปอาหารภายหลัง:** เพิ่มฟิลด์ `photo: 'photos/xxx.jpg'` ในร้านใน `data.js` แล้วรูปจะมาแทนไอคอนอัตโนมัติ (อย่าลืมเพิ่มไฟล์รูปใน `ASSETS` ของ `sw.js` เพื่อให้ใช้ออฟไลน์ได้)

**หมายเหตุข้อมูล:** ร้าน ราคา คูปอง และคะแนนเป็นข้อมูลตัวอย่างเพื่อการเรียน ไม่ใช่ดีลจริงกับร้านค้า

## 🏆 5. จุดเด่นสำหรับคะแนนสอบ TU109 (Grading Criteria Alignment)

| เกณฑ์การประเมิน TU109 | สิ่งที่โปรเจกต์ตอบโจทย์ |
| :--- | :--- |
| **Problem Identification** | แก้ปัญหาเรื่องคิดไม่ออก, การคุมงบการเงินนักศึกษา, และความขัดแย้งเวลาเลือกอาหารกับเพื่อน |
| **Value Proposition** | มอบความคุ้มค่าที่จับต้องได้ทันที (เงินที่ประหยัดได้จากคูปอง > ค่าบริการ Subscription) |
| **Business Model Feasibility** | มีกระแสรายได้สม่ำเสมอ (Recurring Revenue) จากผู้ใช้ และรายได้ค่าโฆษณา/โปรโมตจากร้านค้า (B2B2C) |
| **Technical Feasibility** | สถาปัตยกรรม Offline-First ตอบโจทย์ข้อกำหนดอาจารย์ มีเสถียรภาพสูง ไม่พึ่งพาคลาวด์ภายนอก |
| **User Experience (UX/UI)** | ออกแบบตามมาตรฐานวิศวกรรมซอฟต์แวร์ สวยงาม ใช้งานง่าย มีเกมและปฏิสัมพันธ์ที่น่าประทับใจ |
